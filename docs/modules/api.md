# api module

## Purpose

The HTTP contract. `api/openapi.yaml` (OpenAPI 3.1) is the source of truth for every consumer, consumer self-service and admin endpoint; `internal/api/` holds the server interfaces ogen generates from it (D-32, D-57). Other modules implement the generated `Handler` and `SecurityHandler`; nothing hand-writes routing, request decoding or response encoding.

## Owns

- Files: `api/openapi.yaml` (the contract) and `internal/api/ogen.yml` (generator settings).
- Packages: `internal/api/` (built by PLT-F-001). The `oas_*_gen.go` files are generated by `go generate ./internal/api/...` (`go tool ogen`) and never edited by hand; `doc.go` and `contract_test.go` are hand-written.
- Tables: none.
- Port: the generated server interfaces, `Handler` (one method per operation, plus `NewError`, which maps a handler error to the shared error response) and `SecurityHandler` (`accessKeyAuth` bearer key, `consumerSessionAuth` and `adminSessionAuth` cookies). `UnimplementedHandler` answers every operation a ticket has not built yet.
- Lint: `go tool vacuum lint api/openapi.yaml` (vacuum's recommended ruleset) must report no errors. CI runs the lint and checks that regenerating `internal/api` changes nothing.

## Imports

Generated code imports only the standard library and ogen's runtime: `github.com/ogen-go/ogen` (`conv`, `http`, `json`, `middleware`, `ogenerrors`, `ogenregex`, `uri`, `validate`), `github.com/go-faster/jx`, `github.com/go-faster/errors` and `github.com/google/uuid` (for `format: uuid`). Client, webhook and OpenTelemetry generation are off (`ogen.yml`), so it does not import OpenTelemetry; telemetry goes through the `Telemetry` port (D-31).

`internal/api` imports no other local-server module. The modules that serve the API import it. Allowed and forbidden imports are enforced by `tools/archcheck` (`go run ./tools/archcheck`): no import cycles between modules, adapters imported only from `cmd/`, drivers only in their owning module. Core modules import ports, never adapters.

## Decisions

D-32 (spec-first, standard surfaces as published, additive contracts, error envelope and typed codes, explicit rejection of unsupported fields), D-33 (`LS-Request-Properties`, `LS-Receipt`), D-57 (ogen and vacuum as `go tool` directives), D-05, D-26, D-27, D-48, D-51 (`unmetered` receipts), D-52 (receipts carry leaf index and tree size), D-54 (every limit is a setting; no bounds hierarchy), D-10 (`/admin/v1` on the admin listener only), D-66. The module map is in `docs/design_docs/lld.md` section 1.
